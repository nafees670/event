## Phase 1 — Auth, roles & contact gate

| #    | Decision                                                                                                                                                                                                                                                                                                  | Why                                                                                                                                                                  |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.1  | Refresh tokens are stored server-side (`RefreshSession`, TTL index). Rotation claims the old token atomically; reuse bumps `refreshTokenVersion` and deletes all sessions.                                                                                                                                | This is what §8.7 asks for (rotation + reuse detection) and it supports several devices per user.                                                                    |
| 1.2  | A rotated token presented again **within 10 s** returns `401 REFRESH_CONFLICT` and revokes nothing. The client retries once.                                                                                                                                                                              | Two tabs refreshing at the same moment would otherwise trip reuse detection and log the user out. Both tabs share the cookie jar, so the retry sends the new cookie. |
| 1.3  | The access token is kept **in memory only**; the session is restored on load through `/auth/refresh`.                                                                                                                                                                                                     | Keeps it out of XSS-readable storage.                                                                                                                                |
| 1.4  | The refresh cookie is `SameSite=Strict` (as specified) and `Secure` only in production. Refresh and logout also reject foreign `Origin` headers. **Web and API must share a registrable domain in production.**                                                                                           | Chrome sends no SameSite=Strict cookies cross-site. localhost:3000 → :4000 counts as same-site.                                                                      |
| 1.5  | Lockout and the login limiter return **429** (`ACCOUNT_LOCKED` / `RATE_LIMITED`) with `Retry-After`. Lockout is per email across all IPs. Unknown emails get the same response and the same bcrypt timing.                                                                                                | No account enumeration.                                                                                                                                              |
| 1.6  | `bcryptjs` instead of native `bcrypt`. Cost comes from `BCRYPT_ROUNDS` (12; tests use 4).                                                                                                                                                                                                                 | npm 11 blocks native install scripts; bcryptjs needs none.                                                                                                           |
| 1.7  | Forgot-password always returns 200. The reset token is 32 random bytes, stored as SHA-256 only, valid 30 min and single-use. A reset logs out every session and clears the lockout. Without SMTP in dev, the email (including the link) is **logged to the console**. SMTP is now required in production. | Forgot-password has to work before Phase 5's email work.                                                                                                             |
| 1.8  | Every WhatsApp button calls **`POST /contact/whatsapp`** (auth, 30/h per user) with the picker data in the body. `GET /contact/admin` (spec) also exists. `GET /operators/:slug/contact` arrives in Phase 2 for call / number reveal.                                                                     | Keeps notes, dates and other personal data out of URLs and logs. One endpoint holds the `WHATSAPP_ROUTING` logic.                                                    |
| 1.9  | Contact picker copy and options live in `Setting{key:'contact'}`, falling back to `DEFAULT_CONTACT_SETTINGS`. Public `GET /settings/contact` never includes a number. The admin UI comes in a later phase.                                                                                                | Matches §8.1 (admin-editable).                                                                                                                                       |
| 1.10 | Logging WhatsApp clicks as `Inquiry` records waits for **Phase 5**, when the Inquiry model exists.                                                                                                                                                                                                        | Avoids a throwaway model now.                                                                                                                                        |
| 1.11 | `/login` is a **full page** on every screen size (the spec allows a desktop modal but doesn't require it).                                                                                                                                                                                                | One code path; intercepting-route modals can come later if wanted.                                                                                                   |
| 1.12 | The pending action lives in `sessionStorage` (expires after 30 min). It resumes only when the user is back on the `returnTo` **path**. The login heading takes the operator name from it (no extra fetch).                                                                                                | Covers "never click twice" without trusting URL params for display.                                                                                                  |
| 1.13 | Once logged in, the **account's `themePreference` wins** over the browser's stored theme. Toggling while logged in saves to the account.                                                                                                                                                                  | §4: the user's choice is saved on the User.                                                                                                                          |
| 1.14 | Dashboard guards (`RequireAuth`) are client-side UX only. The API enforces auth and roles.                                                                                                                                                                                                                | The access token isn't available to Next middleware (memory only).                                                                                                   |
| 1.15 | `/register/operator` moves to **Phase 2** (it needs the Operator and City models). Terms / Privacy links appear once those pages exist.                                                                                                                                                                   | No dead links.                                                                                                                                                       |
| 1.16 | Toasts use **sonner**, themed from next-themes. 429 `RATE_LIMITED` shows "Thori der baad try karein…".                                                                                                                                                                                                    | Small and accessible; matches §8.8.                                                                                                                                  |
| 1.17 | API tests run against a **real MongoDB**, with a throwaway DB per test file (`TEST_MONGODB_URI`; CI service container).                                                                                                                                                                                   | No 100 MB mongodb-memory-server download, and behaviour matches production.                                                                                          |

## Pre-Phase-2 fixes (from the project review)

| #   | Decision                                                                                                                                                                                                                         | Why                                                                                                                                                                                                                                 |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F.1 | `autoIndex: false` everywhere. **`ensureIndexes()` runs at boot** and awaits `createIndexes()` for every registered model. The server exits if an index can't be built. `npm run db:indexes [-- --sync]` exists for manual runs. | Before this fix, production never built indexes: no unique email, no TTL on sessions. Explicit, awaited and logged beats mongoose's silent background autoIndex. `createIndexes` never drops anything, so it is safe on every boot. |
| F.2 | `TRUST_PROXY` env (number of proxies). Defaults to 0 outside production and **is required in production**.                                                                                                                       | A hard-coded 1 lets clients spoof IPs when there is no proxy. A 0 behind a proxy puts every user in one rate-limit bucket. Neither should happen silently.                                                                          |
| F.3 | The login page **clears a saved pending action** unless its action, target and returnTo match the URL.                                                                                                                           | An abandoned contact click used to fire later, after an unrelated login.                                                                                                                                                            |

## Phase 2 — Catalogue

| #    | Decision                                                                                                                                                                                                                                                                                                                                                    | Why                                                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2.1  | **Admin-created operators get an invite email** (a set-password link: the reset-token mechanism with a 72 h TTL). The admin never sets or sees a password.                                                                                                                                                                                                  | No shared or temporary passwords.                                                                                                                    |
| 2.2  | **Operator self-signup** (`POST /auth/register/operator`) creates the account plus a `pending` profile and logs them in. While pending they can edit their profile and drones; public pages return 404 until an admin approves.                                                                                                                             | Matches "approve self-registered operators" (§5).                                                                                                    |
| 2.3  | **Deactivate** (→ `inactive`) revokes all of that operator's sessions. **Delete** removes the profile and drones; the person keeps a customer account (logged out).                                                                                                                                                                                         | A removed operator must not stay logged in.                                                                                                          |
| 2.4  | Operator slugs are **stable**: renaming the business doesn't change the URL.                                                                                                                                                                                                                                                                                | Shared links and SEO keep working.                                                                                                                   |
| 2.5  | `Operator.priceFrom` + `priceSort` are **denormalised** (lowest available per-event price; unpriced sort last).                                                                                                                                                                                                                                             | Price sort/filter needs no aggregation per request.                                                                                                  |
| 2.6  | Public search uses the Mongo **text index** (word match, ranked). Admin search uses an escaped **regex** on business name (partial match).                                                                                                                                                                                                                  | Spec asks for a text index; admins need "type part of a name".                                                                                       |
| 2.7  | Public operator JSON is built **only** by the serializers in `services/catalog.ts`. The phone is never selected, and WhatsApp becomes `hasWhatsapp`. Tests scan every public response for a number.                                                                                                                                                         | §2.1: numbers must never leak, even by accident.                                                                                                     |
| 2.8  | `GET /operators/:slug/contact` (call / number reveal) returns the **admin number while routing=admin** (`routedTo: 'admin'`; the UI explains it), and the operator's own numbers only when routing=operator. `Setting{contact}.whatsappRouting` can override the env flag.                                                                                  | §8.1: with admin routing, operator numbers stay private.                                                                                             |
| 2.9  | `POST /contact/whatsapp` **looks up the operator name from the DB** when an `operatorSlug` is sent, ignoring the client's label.                                                                                                                                                                                                                            | The admin can trust the lead's operator name.                                                                                                        |
| 2.10 | Operator photos and drone images must be **`https://res.cloudinary.com/…`**. Upload UI arrives in Phase 3; until then, initials and drone placeholders are shown.                                                                                                                                                                                           | next/image allow-list; no third-party image hosts or trackers.                                                                                       |
| 2.11 | `Operator.photoUrl` (business photo) is separate from `User.avatarUrl`.                                                                                                                                                                                                                                                                                     | The brand image can differ from the owner's avatar.                                                                                                  |
| 2.12 | **Seed** is idempotent (upserts by slug/email) and never resets an existing admin's password. Specs and "best for" are `[… edit in admin]` placeholders. **Sample prices (PKR 25k–60k) are placeholders.** Sample operator #6 is `pending`, to show the approval queue. `--prod` seeds only admin, cities and drones; sample data is refused in production. | §10, plus safe production seeding.                                                                                                                   |
| 2.13 | **`patchSchema(shape)`** helper for every PATCH body.                                                                                                                                                                                                                                                                                                       | Zod 4's `.partial()` keeps defaults: a PATCH of `bio` reset service cities and experience, and a city rename re-activated the city. Caught by tests. |
| 2.14 | Optional text and price fields sent empty **clear** the value (`null`). An empty WhatsApp falls back to the phone number.                                                                                                                                                                                                                                   | `''`/`null` → `undefined` was silently ignored by Mongoose, so fields could never be cleared.                                                        |
| 2.15 | **Removed mongoose `sanitizeFilter`**. Global mongoose settings now live in `configureMongoose()`, used by both server and tests. Operator injection is blocked by express-mongo-sanitize plus Zod, with regression tests.                                                                                                                                  | `sanitizeFilter` broke our own `$in` queries in the real server, while tests (different settings) passed.                                            |
| 2.16 | No transactions (standalone local Mongo). Operator creation **compensates** (deletes the user) if the profile insert fails.                                                                                                                                                                                                                                 | Atlas supports transactions; this can switch to sessions later.                                                                                      |
| 2.17 | City delete is blocked (409) while operators use the city, so the admin deactivates instead. Drone delete is blocked while any operator lists the drone.                                                                                                                                                                                                    | No dangling references.                                                                                                                              |
| 2.18 | The **"event" filter** on operators and drones is deferred to **Phase 3**.                                                                                                                                                                                                                                                                                  | Events come from shorts (`Short.eventType`); operators have no event field in §6.                                                                    |
| 2.19 | `/drones` filters are city, budget (max per-event price) and sort. The model cards themselves are the "model" choice.                                                                                                                                                                                                                                       | Fits §5.3 without a separate offerings page.                                                                                                         |
| 2.20 | Caching: public API `Cache-Control: public, max-age=60, stale-while-revalidate=300`; Next ISR 60 s. **Admin edits show on public pages within about 60 s.** Phase 8 adds tag invalidation and Redis. The filter dropdown keeps a URL value visible even if its option isn't cached yet.                                                                     | Simple now; precise invalidation belongs to the scale phase.                                                                                         |
| 2.21 | `generateMetadata` uses `serverApi(…, { allowMissing: true })` (returns `null` on 404); only the page calls `notFound()`. List skeletons live in `(list)/loading.tsx`, never above `[slug]`.                                                                                                                                                                | Streamed metadata otherwise leaves missing pages at 200. Verified on a production build: pending/unknown operator, drone or city → 404.              |
| 2.22 | Mobile navigation is a small dropdown menu until the Phase 4 bottom nav.                                                                                                                                                                                                                                                                                    | Header links don't fit at 375 px.                                                                                                                    |
| 2.23 | The admin overview is minimal (counts plus the approval queue). The full KPI dashboard comes in Phase 7.                                                                                                                                                                                                                                                    | Scope.                                                                                                                                               |

## Phase 3 — Media & shorts

| #    | Decision                                                                                                                                                                                                                                                 | Why                                                                                                               |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 3.1  | **Signed direct uploads** (§8.2). The signature includes `folder: video-lamhe/<kind>/<userId>`, so a signature only works for the requester's own folder.                                                                                                | The API never streams video, and nobody can submit someone else's upload.                                         |
| 3.2  | After upload the API **re-checks with Cloudinary** (`explicit()`: exists, duration ≤ 60 s, ≤ 100 MB) and destroys files that are too long or too large. The browser checks the same limits first, for UX.                                                | Browser checks can be bypassed.                                                                                   |
| 3.3  | Cloudinary is behind a **`MediaService` interface**; tests use an in-memory fake. Without keys, dev still boots and uploads return 503 `MEDIA_NOT_CONFIGURED`. Production requires the keys.                                                             | Tests and dev don't need an account; a misconfigured production can't start.                                      |
| 3.4  | **Likes in a `ShortLike` collection** (unique short + user) plus a `Short.likeCount` counter, instead of the spec's `likes: [ref User]`. Saves live in `SavedShort`.                                                                                     | An array grows without bound (16 MB doc limit) and bloats every feed read. Idempotent like/unlike comes for free. |
| 3.5  | Public feed responses carry **no viewer-specific fields**. The viewer's likes and saves come from `GET /shorts/engagement?ids=…` (auth, no-store).                                                                                                       | Feed responses stay cacheable (`public, max-age=30`) by CDN and ISR without leaking per-user data.                |
| 3.6  | `Short.operatorActive` is denormalised and synced when an operator's status changes. The feed shows `published` + `operatorActive` only.                                                                                                                 | A deactivated operator's shorts disappear without a join on every feed query.                                     |
| 3.7  | Feed pagination uses an **opaque cursor** (base64 of `createdAt_id`, sorted `createdAt desc, _id desc`).                                                                                                                                                 | Spec: cursor for feeds; no `skip`; stable when new shorts arrive.                                                 |
| 3.8  | Operator uploads are always `pending`. Operators can edit metadata only while not published; editing a rejected short sends it back to `pending` (the reason is cleared). Admin uploads may publish directly, as draft or featured.                      | §5 operator → approval flow.                                                                                      |
| 3.9  | Views = **2 s of real playback, once per short per browser session**, as a plain Mongo `$inc` (engagement limiter 60/min). Redis INCR + flush arrives in Phase 8.                                                                                        | Cheap, honest enough for now; the spec's scale plan stays intact.                                                 |
| 3.10 | Gated **like/save always apply after login** (never toggle off), so the "never click twice" rule holds. Engagement state is cleared on logout.                                                                                                           | §2.1, and a shared device must not show the previous user's likes.                                                |
| 3.11 | The feed mounts a real `<video>` only for the active short ± 1 (the rest show posters). It plays at ≥ 60 % visibility, pauses otherwise, and never autoplays under `prefers-reduced-motion`. No unmute control, because `ac_none` strips audio per spec. | Memory/bandwidth on phones; §8.2.                                                                                 |
| 3.12 | Share links are `/shorts?start=<id>` (that short first, then the feed) rather than a separate per-short page.                                                                                                                                            | One player; no duplicate page type to maintain.                                                                   |
| 3.13 | Operator photo and drone images must be uploads to **our** cloud (`isOurAssetUrl`). Replaced or removed images are destroyed fire-and-forget. Signup hides the photo uploader (uploads need a logged-in operator).                                       | §8.2 "destroy the old asset"; no foreign image hosts.                                                             |
| 3.14 | The event filter on operators and drones uses published shorts (`Short.distinct('operator', {eventType})`).                                                                                                                                              | Closes decision 2.18.                                                                                             |
| 3.15 | Home (still a placeholder until Phase 4) shows a **featured shorts row** (falling back to the latest) with ISR 60 s via `serverApiSafe()`. `next build` succeeds even without a running API.                                                             | Phase 3 done-criterion "appears on Home"; CI builds without an API.                                               |
| 3.16 | Seed adds 12 **sample shorts that point at Cloudinary's public `demo` account** (`isSample: true`, no public id, never destroyed, never seeded with `--prod`).                                                                                           | Local dev has real playable videos without uploading anything.                                                    |
| 3.17 | The floating WhatsApp button is hidden on `/shorts`, because every short has its own WhatsApp action.                                                                                                                                                    | Avoids two overlapping WhatsApp buttons.                                                                          |
